# Data minimisation

We only use the data the plan needs. This table is generated by `scripts/ingest.ts` from its keep/drop policy; do not edit it by hand.

- The raw CSVs live in `data/`, which is gitignored and never committed or deployed. The late customer orders (`docs/spec-update/warehouse_extra_orders.csv`) are committed because they hold no personal data beyond a pseudonymous label.
- Only the sanitised JSON in `fixtures/` reaches the app, the repository or any AI tool.
- An unknown column stops the ingest, so new personal data cannot be kept by default.

## bins.csv (34 rows)

| Column | Decision | Why |
|---|---|---|
| `bin_code` | Kept | Identifies the bin; needed for every move. |
| `zone` | Kept | Human-readable location for the floor view. |
| `bin_size` | Kept | Size class must match the product (store rule 4). |
| `capacity_units` | Kept | Capacity in units (store rule 2). Blank means unknown and is flagged. |

## products.csv (27 rows)

| Column | Decision | Why |
|---|---|---|
| `sku` | Kept | Product code; links stock, incoming and moves. |
| `name` | Kept | Shown on the plan so staff recognise the product. |
| `category` | Kept | Grouping for display. |
| `bin_size` | Kept | Size class must match the bin (store rule 4). |
| `unit_cost_gbp` | Dropped | Not needed: the plan is about space, not value. |
| `reorder_point` | Dropped | Only needed for the run-out stretch goal (not in the MVP). |
| `reorder_qty` | Dropped | Not needed for consolidation or putaway. |
| `supplier` | Dropped | Supplier name is already on the incoming list where it is needed. |
| `supplier_contact_email` | Dropped | Personal/contact data; never needed. |
| `supplier_contact_mobile` | Dropped | Personal/contact data; never needed. |

## stock.csv (33 rows)

| Column | Decision | Why |
|---|---|---|
| `bin_code` | Kept | Which bin holds the stock. |
| `sku` | Kept | Which product is in the bin. |
| `quantity` | Kept | Units counted; the count is treated as truth. |
| `last_counted` | Kept | Used to flag counts that are out of date. |
| `counted_by` | Dropped | Staff name; personal data and not needed. |
| `counter_personal_mobile` | Dropped | Personal mobile number; never needed. |
| `counter_home_address` | Dropped | Home address; never needed. |

## incoming.csv (6 rows)

| Column | Decision | Why |
|---|---|---|
| `reference` | Kept | PO or work-order number staff look for on delivery. |
| `expected_date` | Kept | Orders the putaway plan. |
| `source` | Kept | Supplier delivery or production run. |
| `supplier` | Kept | Company name only (no contact details); shown on the plan. |
| `sku` | Kept | Product being received. |
| `quantity` | Kept | Units to place. |

## movements.csv (312 rows)

| Column | Decision | Why |
|---|---|---|
| `movement_id` | Dropped | Row identifier; not needed. |
| `date` | Kept | Counts days of history for run-out cover (stretch view). |

## warehouse_extra_orders.csv (3 rows)

| Column | Decision | Why |
|---|---|---|
| `order_ref` | Kept | Identifies the order on the plan and in the pitch. |
| `customer` | Kept | Kept only because it is already a pseudonymous label (for example "Customer 14"); a real name or contact would be dropped. |
| `delivery_date` | Kept | Decides when the stock leaves the stores. |
| `sku` | Kept | Product ordered; links to its size class. |
| `quantity` | Kept | Units that leave the stores. |

**Summary:** 27 columns kept, 15 dropped. No names, phone numbers, home addresses or contact details are kept.
